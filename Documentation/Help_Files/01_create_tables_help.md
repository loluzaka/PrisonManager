# Help: `01_create_tables.sql`

## 1. File overview

* **Exact filename:** `01_create_tables.sql`
* **Location:** `sql/`
* **Purpose:** Creates the seven core tables with primary keys, foreign keys, NOT NULL, UNIQUE, CHECK and DEFAULT constraints and identity IDs.
* **Feature(s):** F1 (normalised schema), F2 (integrity constraints), F3 (referential integrity and delete rules)
* **Member responsibility:** Member 1
* **Role in the system:** Foundation of the whole database: every trigger, procedure, view and test works on these tables.
* **Execution order:** After `00_admin_setup.sql`; before `02_alter_schema.sql`.

## 2. Required database objects and dependencies

* **Needs:** schema `PRISON_OWNER` with CREATE TABLE (script 00).
* **Creates (in this order, parents first):** BLOCKS, INMATES, VISITORS, VISITS, MOVEMENTS, CONFLICTS, AUDIT_LOG.
* **Foreign-key dependency:** INMATES -> BLOCKS; VISITS -> INMATES, VISITORS; MOVEMENTS -> INMATES, BLOCKS (twice); CONFLICTS -> INMATES, VISITORS. AUDIT_LOG has none on purpose.
* **Needed by:** every later script. Evolved by `02_alter_schema.sql`.

## 3. Keyword and syntax explanation

| Keyword / concept | What it means | Syntax | Why it is used in THIS file |
|---|---|---|---|
| **CREATE TABLE** | Defines a new table: its columns, data types and constraints. The table starts empty. | `CREATE TABLE name (col type [constraint], ..., [table constraint]);` | Seven statements, one per entity. |
| **IDENTITY** | A column whose value the database generates automatically (replaces a hand-made sequence + trigger). | `col NUMBER GENERATED BY DEFAULT AS IDENTITY` | Every table has `<name>_id NUMBER GENERATED BY DEFAULT AS IDENTITY` as its surrogate key; BY DEFAULT lets `04_seed_data.sql` insert fixed IDs. |
| **PRIMARY KEY** | Uniquely identifies a row; implies NOT NULL + UNIQUE and creates an index. | `col type CONSTRAINT pk_x PRIMARY KEY` | Named `pk_<table>`. |
| **FOREIGN KEY** | Makes a column (or columns) point at the primary key of another table so orphans cannot exist (referential integrity). | `col type CONSTRAINT fk_x REFERENCES parent (key)` | Named `fk_...`; MOVEMENTS has two (`fk_mov_from`, `fk_mov_to`) to BLOCKS. |
| **ON DELETE (NO ACTION)** | What happens to children when a parent row is deleted. Oracle default is NO ACTION: the delete is refused. This is Oracle's equivalent of RESTRICT. | `... REFERENCES parent (key) [ON DELETE CASCADE | SET NULL]` | No ON DELETE clause is written, so history can never be deleted by accident (F3). |
| **NOT NULL** | Column must always have a value. | `col type NOT NULL` | On every column that must always be known. |
| **UNIQUE** | No two rows may share the value (or combination of values); NULLs are ignored. Creates an index. | `CONSTRAINT uq_x UNIQUE (col1, col2)` | `uq_blocks_name`, `uq_inmates_no`, `uq_visitors_idproof (type, number)`, `uq_visits_inmate_slot (inmate, date, slot)` prevents double booking, `uq_conf_pair`. |
| **CHECK** | A condition every row must satisfy (domain integrity). | `CONSTRAINT ck_x CHECK (capacity > 0)` | Domain rules, e.g. `capacity > 0`, `sentence_end > sentence_start`, status/slot lists, `visit_date = TRUNC(visit_date)`. |
| **DEFAULT** | Value used when an INSERT does not mention the column. | `col type DEFAULT expr NOT NULL` | `status DEFAULT 'ACTIVE'`, `approval_status DEFAULT 'PENDING'`, `SYSTIMESTAMP`, `SYS_CONTEXT('USERENV','SESSION_USER')`. |

**Common mistakes with these keywords**

* *CREATE TABLE*: Creating a child table before its parent (the FOREIGN KEY target must exist) -> ORA-00942.
* *IDENTITY*: `BY DEFAULT` lets you supply your own value (the seed does); `ALWAYS` forbids it. Supplying duplicates -> ORA-00001.
* *PRIMARY KEY*: Forgetting to name constraints: error messages then show unreadable SYS_Cnnnn names.
* *FOREIGN KEY*: Inserting a child before its parent -> ORA-02291; deleting a parent that has children -> ORA-02292.
* *ON DELETE (NO ACTION)*: Using CASCADE on history tables silently destroys records. This project deliberately omits it.
* *NOT NULL*: Inserting without the column and without a DEFAULT -> ORA-01400.
* *UNIQUE*: Expecting UNIQUE to forbid several NULLs - it does not.
* *CHECK*: A CHECK cannot contain a subquery or SYSDATE - use a trigger for rules that need other rows or the clock.
* *DEFAULT*: Writing the DEFAULT after NOT NULL (Oracle wants DEFAULT first).

## 4. Tables and columns involved

### BLOCKS

A cell block inside a facility. Capacity and security level drive placement rules (F15).

| # | Column | Data type | Null? | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | **BLOCK_ID** | NUMBER | NOT NULL | `identity (auto-generated)` | PK (identity) | Surrogate primary key. |
| 2 | **BLOCK_NAME** | VARCHAR2(50) | NOT NULL | `—` | — | Unique block name, e.g. A-Block. |
| 3 | **CAPACITY** | NUMBER(4) | NOT NULL | `—` | CK CK_BLOCKS_CAPACITY | Number of beds; must be > 0. Occupancy is computed, never stored. |
| 4 | **SECURITY_LEVEL** | VARCHAR2(10) | NOT NULL | `—` | CK CK_BLOCKS_SECURITY | LOW, MEDIUM or HIGH. An inmate may not be placed in a block whose level is below the risk level of the inmate being placed. |
| 5 | **FACILITY_ID** | NUMBER | NOT NULL | `—` | FK → FACILITIES | Facility owning the block (added by ALTER in 02_alter_schema.sql, made NOT NULL after the seed load). |

Unique constraints: `UQ_BLOCKS_NAME`

Check constraints:

* `CK_BLOCKS_CAPACITY` — `capacity > 0`
* `CK_BLOCKS_SECURITY` — `security_level IN ('LOW','MEDIUM','HIGH')`

Relationships: `FACILITY_ID` → **FACILITIES** (`FK_BLOCKS_FACILITY`, on delete NO ACTION)

### INMATES

A person serving a sentence. Never deleted: status changes instead (soft delete).

| # | Column | Data type | Null? | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | **INMATE_ID** | NUMBER | NOT NULL | `identity (auto-generated)` | PK (identity) | Surrogate primary key. |
| 2 | **INMATE_NO** | VARCHAR2(20) | NOT NULL | `—` | — | Unique prisoner number, e.g. INM-0001. |
| 3 | **FULL_NAME** | VARCHAR2(100) | NOT NULL | `—` | — | Synthetic name. |
| 4 | **DATE_OF_BIRTH** | DATE | NOT NULL | `—` | — | Date of birth (synthetic). |
| 5 | **ADMISSION_DATE** | DATE | NOT NULL | `TRUNC(SYSDATE)` | — | Day the inmate was admitted; defaults to today. |
| 6 | **SENTENCE_START** | DATE | NOT NULL | `—` | CK CK_INMATES_SENTENCE | First day of the sentence. |
| 7 | **SENTENCE_END** | DATE | NOT NULL | `—` | CK CK_INMATES_SENTENCE | Release date; must be after SENTENCE_START. Visits are only allowed inside the sentence period. |
| 8 | **STATUS** | VARCHAR2(12) | NOT NULL | `'ACTIVE'` | CK CK_INMATES_STATUS | ACTIVE (housed), TRANSFERRED (moved to an outside prison) or RELEASED. Only ACTIVE inmates count towards block occupancy and can receive visits. |
| 9 | **BLOCK_ID** | NUMBER | NOT NULL | `—` | FK → BLOCKS | Block where the inmate lives (or last lived). |
| 10 | **RISK_LEVEL** | VARCHAR2(10) | NOT NULL | `'LOW'` | CK CK_INMATES_RISK | LOW, MEDIUM or HIGH (added by ALTER, F15). Must not exceed the block security level. |

Check constraints:

* `CK_INMATES_RISK` — `risk_level IN ('LOW','MEDIUM','HIGH')`
* `CK_INMATES_SENTENCE` — `sentence_end > sentence_start`
* `CK_INMATES_STATUS` — `status IN ('ACTIVE','TRANSFERRED','RELEASED')`

Relationships: `BLOCK_ID` → **BLOCKS** (`FK_INMATES_BLOCK`, on delete NO ACTION)

### VISITS

Associative table: one row per booked visit (INMATES <-> VISITORS many-to-many).

| # | Column | Data type | Null? | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | **VISIT_ID** | NUMBER | NOT NULL | `identity (auto-generated)` | PK (identity) | Surrogate primary key. |
| 2 | **INMATE_ID** | NUMBER | NOT NULL | `—` | FK → INMATES | Inmate being visited. |
| 3 | **VISITOR_ID** | NUMBER | NOT NULL | `—` | FK → VISITORS | Visitor. |
| 4 | **VISIT_DATE** | DATE | NOT NULL | `—` | CK CK_VISITS_DATE_ONLY | Date only (time part must be midnight). |
| 5 | **SLOT** | VARCHAR2(11) | NOT NULL | `—` | CK CK_VISITS_SLOT | One of the six fixed one-hour slots, e.g. 09:00-10:00. |
| 6 | **STATUS** | VARCHAR2(10) | NOT NULL | `'SCHEDULED'` | CK CK_VISITS_STATUS | SCHEDULED, COMPLETED, MISSED or CANCELLED. |
| 7 | **BOOKED_ON** | TIMESTAMP(6) | NOT NULL | `SYSTIMESTAMP` | — | Timestamp when the booking was made. |

* `CK_VISITS_SLOT` — `slot IN ('09:00-10:00','10:00-11:00','11:00-12:00', 			      '14:00-15:00','15:00-16:00','16:00-17:00')`

### MOVEMENTS

History of every block change, including admission. References BLOCKS twice.

| # | Column | Data type | Null? | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | **MOVEMENT_ID** | NUMBER | NOT NULL | `identity (auto-generated)` | PK (identity) | Surrogate primary key. |
| 2 | **INMATE_ID** | NUMBER | NOT NULL | `—` | FK → INMATES | Inmate moved. |
| 3 | **FROM_BLOCK** | NUMBER | NULL | `—` | FK → BLOCKS; CK CK_MOV_DIFF | Origin block; NULL for an admission. |
| 4 | **TO_BLOCK** | NUMBER | NOT NULL | `—` | FK → BLOCKS; CK CK_MOV_DIFF | Destination block. |
| 5 | **MOVEMENT_DATE** | TIMESTAMP(6) | NOT NULL | `SYSTIMESTAMP` | — | When the move happened. |
| 6 | **REASON** | VARCHAR2(200) | NULL | `—` | — | Free text reason (ADMISSION, transfer reason, ...). |
| 7 | **MOVED_BY** | VARCHAR2(60) | NOT NULL | `SYS_CONTEXT('USERENV','SESSION_USER')` | — | Database user who made the change. |

Check constraints:

* `CK_MOV_DIFF` — `from_block IS NULL OR from_block <> to_block`

Relationships: `FROM_BLOCK` → **BLOCKS** (`FK_MOV_FROM`, on delete NO ACTION); `INMATE_ID` → **INMATES** (`FK_MOV_INMATE`, on delete NO ACTION); `TO_BLOCK` → **BLOCKS** (`FK_MOV_TO`, on delete NO ACTION)

### CONFLICTS

Associative table: a visitor who must not meet a given inmate (F14).

| # | Column | Data type | Null? | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | **CONFLICT_ID** | NUMBER | NOT NULL | `identity (auto-generated)` | PK (identity) | Surrogate primary key. |
| 2 | **INMATE_ID** | NUMBER | NOT NULL | `—` | FK → INMATES | Inmate. |
| 3 | **VISITOR_ID** | NUMBER | NOT NULL | `—` | FK → VISITORS | Visitor. |
| 4 | **REASON** | VARCHAR2(20) | NOT NULL | `—` | CK CK_CONF_REASON | RIVAL, VICTIM_RELATIVE, GANG_AFFILIATION or OTHER. |
| 5 | **FLAGGED_DATE** | DATE | NOT NULL | `TRUNC(SYSDATE)` | CK CK_CONF_EXPIRY | Day the conflict was recorded. |
| 6 | **RESOLVED** | CHAR(1) | NOT NULL | `'N'` | CK CK_CONF_RESOLVED | Y when the conflict is resolved (added by ALTER). |
| 7 | **RESOLVED_ON** | DATE | NULL | `—` | — | Resolution date. |
| 8 | **EXPIRY_DATE** | DATE | NULL | `—` | CK CK_CONF_EXPIRY | Optional date after which the conflict no longer applies. |

Unique constraints: `UQ_CONF_PAIR`

Check constraints:

* `CK_CONF_EXPIRY` — `expiry_date IS NULL OR expiry_date >= flagged_date`
* `CK_CONF_REASON` — `reason IN ('RIVAL','VICTIM_RELATIVE','GANG_AFFILIATION','OTHER')`
* `CK_CONF_RESOLVED` — `resolved IN ('Y','N')`

### AUDIT_LOG

Append-only trail of changes, transfers, allowed and denied visit attempts (F22). No foreign keys.

| # | Column | Data type | Null? | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | **AUDIT_ID** | NUMBER | NOT NULL | `identity (auto-generated)` | PK (identity) | Surrogate primary key. |
| 2 | **TABLE_NAME** | VARCHAR2(30) | NOT NULL | `—` | — | Table the event concerns. |
| 3 | **ACTION_TYPE** | VARCHAR2(20) | NOT NULL | `—` | CK CK_AUDIT_ACTION | INSERT, UPDATE, DELETE, TRANSFER, VISIT_BOOKED, VISIT_DENIED or JOB. |
| 4 | **RECORD_ID** | NUMBER | NULL | `—` | — | Id of the affected record. For VISIT_DENIED it is the VISITOR_ID (no visit row exists). |
| 5 | **DETAILS** | VARCHAR2(4000) | NULL | `—` | — | Old -> new values or the denial reason (reason=...). |
| 6 | **CHANGED_BY** | VARCHAR2(60) | NOT NULL | `SYS_CONTEXT('USERENV','SESSION_USER')` | — | Database user. |
| 7 | **CHANGED_AT** | TIMESTAMP(6) | NOT NULL | `SYSTIMESTAMP` | — | Timestamp of the event. |

Check constraints:

* `CK_AUDIT_ACTION` — `action_type IN ('INSERT','UPDATE','DELETE','TRANSFER',					     'VISIT_BOOKED','VISIT_DENIED','JOB')`

**Why this structure:** Each fact is stored once (BCNF, see `ER_Diagram.md`); associative tables VISITS, CONFLICTS and MOVEMENTS resolve the many-to-many relationships; AUDIT_LOG has no foreign keys so audit rows survive anything. Note: the columns RISK_LEVEL, FACILITY_ID, RESOLVED, RESOLVED_ON, EXPIRY_DATE shown above are added by `02_alter_schema.sql`, not by this file.

## 5. Walkthrough

1. **BLOCKS** - parent of INMATES, so created first. Constraint `ck_blocks_security` limits `security_level` to LOW/MEDIUM/HIGH.
2. **INMATES** - `status` is the soft-delete switch; `ck_inmates_sentence` forces `sentence_end > sentence_start`; `fk_inmates_block` points at BLOCKS.
3. **VISITORS** - the pair (`id_proof_type`, `id_proof_number`) is unique, so one identity cannot be registered twice. `approval_status` starts as PENDING.
4. **VISITS** - the associative table. `ck_visits_slot` restricts `slot` to six fixed hours; `uq_visits_inmate_slot` stops two bookings for the same inmate, date and slot.
5. **MOVEMENTS** - `from_block` is nullable (an admission has no origin); `ck_mov_diff` forbids moving a block to itself.
6. **CONFLICTS** - `uq_conf_pair` allows one row per inmate/visitor pair (re-flagging reactivates it, see `sp_add_conflict`).
7. **AUDIT_LOG** - action list limited by `ck_audit_action`; user and timestamp are filled by defaults so a caller cannot forge them by omission.

## 8. Common errors and debugging

| Symptom / error | Cause | How to diagnose and fix |
|---|---|---|
| `ORA-00955: name is already used by an existing object` | Tables exist from a previous run | Run `99_drop_all.sql` first (`install.ps1 -Fresh`). |
| `ORA-00942` while creating INMATES | Parent BLOCKS missing | Keep the creation order; do not run statements out of sequence. |
| `ORA-02270: no matching unique or primary key` | FOREIGN KEY targets a column that is not a key | Reference the parent's PRIMARY KEY. |
| `ORA-01408`/`ORA-00957` on duplicate names | Two constraints share a name | Constraint names are unique per schema. |

## 9. Viva questions and answers

**Q1. Why are IDs surrogate (identity) and not the inmate number?**  
A surrogate key is small, never changes and keeps foreign keys short; the natural key (`inmate_no`) is still protected by UNIQUE.

**Q2. What is the difference between PRIMARY KEY and UNIQUE?**  
A table has one primary key (NOT NULL + unique); it can have many UNIQUE constraints which allow NULLs.

**Q3. Why no ON DELETE CASCADE?**  
History (visits, movements, audit) must never disappear automatically; deletion is refused (ORA-02292) and status columns are used instead (soft delete).

**Q4. Why does AUDIT_LOG have no foreign keys?**  
Denied visit attempts refer to records that were never created, and audit rows must survive even if the described row is later removed.

**Q5. What does `uq_visits_inmate_slot` protect?**  
The same inmate cannot be booked twice at the same date and slot (double booking).

**Q6. Is the schema in BCNF?**  
Yes: every determinant is a key (proof in `ER_Diagram.md`).
