# Help: `04_seed_data.sql`

## 1. File overview

* **Exact filename:** `04_seed_data.sql`
* **Location:** `sql/`
* **Purpose:** Rebuilds the same synthetic dataset every time it runs: 2 facilities, 5 blocks, 50 inmates, 40 visitors, 100 visits, 8 conflicts, 3 rivalries, 58 movements and audit history.
* **Feature(s):** F33 (sample data and seed scripts); also the "add NOT NULL after loading" step of F4
* **Member responsibility:** Member 1
* **Role in the system:** Gives every report, cursor, rule and test something to work on. Re-run by `run_tests.ps1` before every test run.
* **Execution order:** After the indexes (03). Safe to re-run at any time: it disables the triggers while loading and re-enables them afterwards.

## 2. Required database objects and dependencies

* **Needs:** all tables (01, 02), not the triggers (they may or may not exist).
* **Clears first:** VISITS, CONFLICTS, INMATE_CONFLICTS, MOVEMENTS, INMATES, VISITORS, AUDIT_LOG (TRUNCATE).
* **MERGEs** FACILITIES and BLOCKS (fixed IDs) so STAFF_ACCESS rows survive a re-seed.
* **Needed by:** everything that demonstrates behaviour; tests A08-A13 assert the row counts.
* **WARNING:** it deletes audit history - never run it against real data.

## 3. Keyword and syntax explanation

| Keyword / concept | What it means | Syntax | Why it is used in THIS file |
|---|---|---|---|
| **ALTER TRIGGER ... DISABLE** | Switches a trigger off/on without dropping it. | `ALTER TRIGGER trg DISABLE;` | All enabled triggers are switched off so seed rows do not create audit/movement rows and historic visits are allowed; enabled again at the end. |
| **DELETE** | Removes rows (can be rolled back, fires triggers). | `DELETE FROM t WHERE cond;` | Child tables before parents. |
| **TRUNCATE** | Deletes all rows instantly, resets the high-water mark, cannot be rolled back, fires no row triggers. | `TRUNCATE TABLE t;` | `TRUNCATE TABLE audit_log` - DDL does not fire the append-only row trigger, so the log can be reset by the owner. |
| **MERGE** | "Upsert": updates the row if it exists, inserts it if not, in one statement. | `MERGE INTO t USING (src) s ON (cond) WHEN MATCHED THEN UPDATE ... WHEN NOT MATCHED THEN INSERT ...` | Repeatable load of facilities and blocks. |
| **DECLARE / BEGIN / END** | The three parts of a PL/SQL block: declarations, executable code, end. An anonymous block has no name and is not stored. | `DECLARE v NUMBER; BEGIN ...; EXCEPTION WHEN ... THEN ...; END;` | Three PL/SQL blocks: people and conflicts; movements; visits. |
| **INSERT** | Adds rows. | `INSERT INTO t (cols) VALUES (...); INSERT INTO t (cols) SELECT ...;` | Row-by-row and `INSERT ... SELECT ... UNION ALL`. |
| **CASE** | Conditional expression inside SQL or PL/SQL. | `CASE WHEN x > 1 THEN 'a' ELSE 'b' END` | Chooses block, status, risk level and visit status from the loop counter. |
| **EXECUTE IMMEDIATE** | Runs a SQL string built at run time (needed for DDL inside PL/SQL). | `EXECUTE IMMEDIATE 'ALTER TABLE ...';` | Runs `ALTER TABLE ... GENERATED BY DEFAULT AS IDENTITY (RESTART START WITH LIMIT VALUE)` and `MODIFY ... NOT NULL`. |
| **IDENTITY** | A column whose value the database generates automatically (replaces a hand-made sequence + trigger). | `col NUMBER GENERATED BY DEFAULT AS IDENTITY` | After inserting explicit IDs the generators are restarted at max+1 so the next normal INSERT does not collide. |
| **ALTER TABLE** | Changes an existing table: add/modify/drop columns, add constraints. | `ALTER TABLE t ADD (col type ...); ALTER TABLE t MODIFY (col NOT NULL); ALTER TABLE t ADD CONSTRAINT ...` | `ALTER TABLE blocks MODIFY (facility_id NOT NULL)` after the data is loaded (ORA-01442 on a re-run is ignored). |
| **Scalar functions** | Row-level functions: UPPER, TRIM, SUBSTR, INSTR, REPLACE, LENGTH, ROUND, MOD, TO_CHAR, ADD_MONTHS, TRUNC(date) ... | `UPPER(TRIM(name))` | MOD, LPAD, ADD_MONTHS, TRUNC, FLOOR build names, dates and deterministic patterns. |
| **COMMIT / ROLLBACK** | COMMIT makes the transaction permanent and releases locks; ROLLBACK undoes everything since the last COMMIT. | `COMMIT; ROLLBACK;` | One COMMIT at the end. |
| **SET (SQL*Plus)** | Session settings of the SQL*Plus client: SERVEROUTPUT, LINESIZE, PAGESIZE, FEEDBACK, VERIFY, ECHO. | `SET LINESIZE 160` | `SET SERVEROUTPUT ON`, `SET FEEDBACK OFF`. |

**Common mistakes with these keywords**

* *ALTER TRIGGER ... DISABLE*: Forgetting to re-enable it afterwards.
* *DELETE*: Forgetting WHERE deletes everything.
* *TRUNCATE*: Using it on a table referenced by an enabled foreign key -> ORA-02266.
* *MERGE*: ON-clause columns cannot be updated in the MATCHED branch.
* *DECLARE / BEGIN / END*: In SQL*Plus a PL/SQL block must be terminated with a line containing only /.
* *INSERT*: Omitting the column list - breaks when columns are added later.
* *CASE*: Missing ELSE returns NULL.
* *EXECUTE IMMEDIATE*: SQL injection risk if the string contains user input; DDL commits implicitly.
* *IDENTITY*: `BY DEFAULT` lets you supply your own value (the seed does); `ALWAYS` forbids it. Supplying duplicates -> ORA-00001.
* *ALTER TABLE*: MODIFY ... NOT NULL fails (ORA-02296) if existing rows contain NULL - load data first.
* *Scalar functions*: Dates: SYSDATE includes the time; use TRUNC(SYSDATE) for "today".
* *COMMIT / ROLLBACK*: DDL (CREATE/ALTER/TRUNCATE) commits implicitly.
* *SET (SQL*Plus)*: These are client commands, not SQL: no semicolon rules apply and they are ignored by other tools.

## 4. Tables and columns involved

All eleven project tables. Rows produced:

| Table | Rows | Pattern |
|---|---|---|
| FACILITIES | 2 | Central Correctional Facility, Riverside Detention Centre |
| BLOCKS | 5 | A (LOW, 14), B (MEDIUM, 12), C (HIGH, 8) in facility 1; D (LOW, 10), E (MEDIUM, 6) in facility 2 |
| INMATES | 50 | 1-45 ACTIVE (A 12, B 11, C 7, D 9, E 6 - E is exactly full), 46-47 TRANSFERRED, 48-50 RELEASED; six due for release in 8-46 days |
| VISITORS | 40 | 1-30 APPROVED, 31-35 PENDING, 36-38 BLACKLISTED, 39-40 REJECTED |
| VISITS | 100 | 8 today, 6 in the next 3 days, 86 in the past 80 days (78 COMPLETED, 4 MISSED, 4 CANCELLED, 14 SCHEDULED in total) |
| CONFLICTS | 8 | 6 active, 1 resolved (inmate 1/visitor 2), 1 expired (inmate 10/visitor 4) |
| INMATE_CONFLICTS | 3 | rivals live in different blocks: (4,14), (6,25), (18,26) |
| MOVEMENTS | 58 | 50 admissions + 8 transfers |
| AUDIT_LOG | 16 | 8 TRANSFER + 8 historic VISIT_DENIED rows written by user `SEED` |

All dates are relative to SYSDATE so the data never goes stale. Names come from generic word lists, ID numbers are `SYN-nnnnnn`; nothing is real.

## 5. Walkthrough

1. **Disable triggers**, then **reset**: DELETE children first; TRUNCATE the audit log.
2. **Facilities and blocks** by MERGE (fixed IDs 1-2 and 1-5).
3. **People loop** (PL/SQL): for inmates 1..50 choose block, status and a risk level that never exceeds the block security level; six inmates get a release date 8-46 days away, three released inmates get dates in the past. 40 visitors cycle through the four ID types.
4. **Conflicts**: 8 visitor/inmate rows; **rivalries**: 3 rows.
5. **Movements**: every inmate has an ADMISSION row; eight inmates (2, 9, 16, 21, 33, 36, 44, 46) also have a transfer from a different "admission block" to their current block, with a matching TRANSFER audit row.
6. **Visits** (100): a loop generates candidates deterministically and keeps one only if it respects *every* rule (approved visitor, ACTIVE inmate, no active conflict, inside the sentence, no duplicate, <= 3 per ISO week per inmate, <= 5 per date+slot). Real run: "visits generated: 100 (candidates tried: 101)".
7. **Audit history**: eight VISIT_DENIED rows from user SEED.
8. **Finish**: add NOT NULL to `blocks.facility_id`, restart identity generators, re-enable the triggers, COMMIT, print the row counts.

Two details that were found by testing: `TRUNCATE TABLE audit_log; -- comment` must not carry a trailing comment (SQL*Plus then mis-parses the line), and the identity of `audit_log`, `movements`, `conflicts`, `inmate_conflicts` is restarted at 1 right after the reset so IDs are identical on every run.

## 8. Common errors and debugging

| Symptom / error | Cause | How to diagnose and fix |
|---|---|---|
| `ORA-02292` during the reset | Deleted a parent before its children | Keep the order VISITS, CONFLICTS, INMATE_CONFLICTS, MOVEMENTS, INMATES, VISITORS. |
| Only 97 visits generated | Deterministic pattern repeats and the 5000-candidate cap is hit | The generator mixes `FLOOR(k/n)` terms into every pattern to avoid cycles (fixed in this version). |
| `ORA-20301` on TRUNCATE? | It cannot happen: TRUNCATE is DDL. If you used DELETE FROM audit_log the immutable trigger refuses it (by design). | Use TRUNCATE as in the script. |
| Counts differ from the tests | Another script changed data | Re-run this script; `run_tests.ps1` does it automatically. |

## 9. Viva questions and answers

**Q1. Why is the seed repeatable?**  
It starts by clearing the tables and uses deterministic formulas, so the same data (relative to today) appears every time - essential for repeatable tests.

**Q2. Why disable triggers while loading?**  
Otherwise every seed row would also create audit/movement rows, historical dates would be refused and INSERT...SELECT would risk the mutating-table error.

**Q3. Why must a generated visit pass every rule inside the seed?**  
The data should be a valid state of the system, as if it had been created through the normal rules.

**Q4. Why relative dates?**  
Demonstrations like "today's roster" and "releases in 30 days" need data near the current date.
